三步，从零到有权限

前置只有一个：手机和你在同一个 Wi-Fi，并且「无线调试」能打开。

01

开无线调试，拿配对码

设置 → 开发者选项 → 无线调试 → 「使用配对码配对设备」，屏幕上会出现 6 位数字和一个端口。

02

填码，让它自己配对

把 6 位数字填进钥痕，点连接。配对完成后它会重新扫连接端口，不用你抄 IP，也不用管端口变了。

03

开始提权，五步走完

校准内核地址 → 定位映射基址 → 注入并取得 root → 验证 root → 交给 KernelSU，每一步都有状态。

常问的几句

没写到的，去酷安或仓库里问。

会不会改坏系统？重启真的能恢复？

不改系统分区，只在当前开机会话里提权，重启后内核状态回到原样。它做的是临时提权，不是刷入式 root；代价是每次重启都要重来一次。

为什么必须要「无线调试」？

它需要一个已经授权的 shell 通道来干活。无线调试配对之后，应用自己就能连上执行命令，不用电脑、不用 Shizuku，也不用你再装别的东西。

配对码一直过期、端口老变怎么办？

无线调试每关一次，端口就会换。钥痕的做法是：连接失败先重扫端口再连；配对只用当场扫到的服务，不会拿旧端口硬连。你只要保证配对框开着的时候把码填进去。

我的机型没在列表里，能用吗？

可以先看设置页的匹配结果。匹配不到时，先从公开共享库里按内核 release 取一份；再不行就导入对应版本的 boot.img 让它自己解析偏移，或导入已经算好的 JSON / HOCON。内核差异太大时确实会失败，这种就只能等适配。

拿到 root 之后能干什么？

交给 KernelSU 管理器接管后，按管理器的规则授权应用。临时 root 的边界也在那里：重启即失效，管理器里的授权不会变成永久。

更新是怎么推的？

应用内检查云端清单，公告、版本、完整性校验三份 JSON 先读国内 Gitee，取不到再回退原地址和镜像；安装包本身放境外，因为 Gitee 不支持大于 10MB 的文件下载。
