CAPABILITY

四件它真能做到的事

它不是一个长期驻留的 root 方案，更像一把一次性的钥匙：用完就走，走完不留门。

临时 root，重启即失效

提权只在本次开机有效。手机一重启就回到干净状态，不需要手动清理，也没有残留的进程。

不刷机，不碰分区

不用解锁 bootloader、不用刷内核、不用动 boot 分区。手机上原来的系统和数据原封不动。

参数可以自己调

不同机型内核不一样，偏移值也就不一样。支持导入 HOCon 格式的 offsets.conf，也可以直接改参数覆盖。

每一步都有记录

攻击日志、内核 dmesg、pstore 都能导出成文件。失败的时候能拿着日志去看是哪一步对不上，而不是只看到一个「失败」。

HOW IT WORKS

三步，全程大概两分钟

1

装上，允许联网

安装包只支持 arm64 设备，系统版本 Android 12 及以上。装好后第一次打开会给一个网络权限，用来下载完整包和更新参数。

2

点「执行」，看着它走

界面上会一条一条列出来：利用内核、构建硬件读写条件、绕过防护。哪一条卡住了，问题就出在那一层。

3

拿到 root，开始用

提权成功后就是普通的 root 环境，可以跑 Shizuku、可以装模块、可以执行命令。想收回去，重启一次就行。

FOR WHOM

它适合谁，不适合谁

适合
  • 想临时跑个 root 工具、跑完就恢复原样的
  • 不想解锁 bootloader、也不想刷坏分区的
  • 手上是 arm64 机型、内核在支持的区间里
  • 愿意自己配 offsets、看得懂日志的
不适合
  • 要一个重启后仍然存在的常驻 root
  • 指望一键搞定、不接受自己调参数的
  • 32 位设备，或内核版本超出区间
  • 不是自己的机器

FAQ

常见问题

这算不算刷机，会不会丢数据
不算。整个过程不写 boot 分区、不动系统镜像，也不要求解锁 bootloader，所以不会清空你的数据。它做的事情在内存层面，重启就消失。
重启之后 root 还在吗
不在。这是「临时 root」，重启即失效，这是设计本身，不是 bug。想要每次开机都自动有 root，得用 KernelSU 或 Magisk 那类常驻方案。
和 KernelSU、Magisk 有什么区别
那两个是常驻的 root 管理器，装模块、给应用授权、重启后还在。Dopamine 只做提权这一件事，做完就结束，不接管后续的权限管理。两个目的不一样，不能互相替代。
提示内核不支持怎么办
先看你的内核版本是不是落在 Linux 5.10.236 ~ 6.6.127 这个区间。落在区间内但仍然失败，多半是 offsets 对不上，去设置里导入对应机型的 offsets.conf（v2），或者打开参数配置手动改，再把 debug 日志导出来看卡在哪一步。
失败会不会把手机搞坏
正常情况下不会，因为它不写入系统分区。如果中途重启了，开机后仍然是原来的系统。设置里有「安全模式」，遇到反复失败可以打开它，把已加载的模块全部禁掉再试。
日志存在哪
设置里打开「导出 Debug 日志到文件」后，写在 Download/dopamine-debug-log 目录里，包含攻击日志、dmesg 和 pstore。要反馈问题，把这几个文件一起发过来最有用。
