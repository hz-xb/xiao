01

它是把一次性的钥匙，不是一扇门

常见的 root 方案会把自己装进系统里：开机自启、管理授权、管着模块。Dopamine 反过来——它只在你按下的这一刻有效。进程结束、手机重启，权限跟着消失，系统里没有留下任何可以再被利用的东西。

所以它不负责「以后」，只负责「现在」。想临时跑一个要 root 的工具、想验证一个一路到底能不能走通，用它就行；想让 root 一直存在，那是另一个东西要解决的问题。

03

它只做这四件事

没有附加功能，也没有顺手塞进去的「优化」。清单就这么短。

临时 root，重启即失效
权限只活在本次开机里。不需要手动清理，也不会有东西在你不知情的时候继续跑。
不刷机，不碰分区
不用解锁 bootloader、不写 boot 分区、不动系统镜像。原来的系统原封不动，数据也不会清。
参数可以自己调
不同机型的内核偏移不一样。支持导入 HOCon 格式的 offsets.conf（v2），也可以直接改参数覆盖。
每一步都留记录
攻击日志、内核 dmesg、pstore 都能导出。失败时能看清是哪一层对不上，而不是只得到一个「失败」。

06

会被问到的

重启之后 root 还在吗

不在。这是临时 root，重启即失效——这是它本来的设计，不是没做完。想让 root 每次开机都在，得用 KernelSU 或 Magisk 那类常驻方案。

和 KernelSU、Magisk 有什么区别

那两个是常驻的 root 管理器：装模块、发授权、重启还在。Dopamine 只做提权这件事，做完就结束，不接管之后的管理。目的不同，不能互相替代。

提示内核不支持怎么办

先确认内核版本在 Linux 5.10.236 ~ 6.6.127 之间。在区间内还失败，多半是 offsets 对不上：去设置里导入对应机型的 offsets.conf（v2），或打开参数配置手改，再把 debug 日志导出来看停在哪一步。

失败会不会把手机弄坏

正常不会，因为整个过程不写系统分区。中途重启，开机还是原来的系统。反复失败可以打开「安全模式」，把已加载的模块全部禁掉再试。

日志在哪

设置里打开「导出 Debug 日志到文件」后，写在 Download/dopamine-debug-log 里，包含攻击日志、dmesg 和 pstore。要反馈问题，把这几份一起发过来最有用。
